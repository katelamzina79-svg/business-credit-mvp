# День 1 — MoSCoW и границы MVP

## Must have
- Авторизация client/banker.
- Выбор продукта: кредит / овердрафт / оборотный.
- Ввод ИНН.
- Автозаполнение данных компании из моков.
- Поля суммы и срока.
- Создание и сохранение черновика.
- Отправка заявки.
- Проверка данных.
- Мок ЕГРЮЛ/ЕГРИП.
- Мок БКИ.
- Скоринг v1.
- Автоматическое решение.
- Статусы и история.
- Кабинет банкира.
- Ручное решение спорной заявки.
- Запрос дополнительных документов.
- Мок подписания.
- Мок выдачи.
- Пустые/ошибочные состояния.
- Docker Compose.

## Should have
- Несколько персонализированных предложений.
- Reason codes.
- Персональная лента новостей/подсказок.
- Факторы скоринга в кабинете банкира.
- Аудит действий банкира.

## Could have
- OCR документов.
- Ollama-помощник.
- Расширенная аналитика.
- Сложная ML-модель.

## Won't have
- Реальные банковские/БКИ интеграции.
- Реальные платежи или выдача денег.
- Реальное электронное подписание.
- Полноценный production KYC/AML.
- React.
- Отдельный frontend build pipeline.
- Сложный ML.

## Definition of MVP
Пользователь выбирает продукт → вводит ИНН и параметры → получает данные компании → отправляет заявку → система проверяет данные → рассчитывает score → принимает/формирует решение → клиент видит решение → при спорном случае банкир меняет решение или запрашивает документы → мок-подписание → мок-выдача.
