# День 2 — BPMN / процесс MVP

```mermaid
flowchart LR
    C[Клиент] --> L[Авторизация]
    L --> P[Выбор продукта]
    P --> I[Ввод ИНН и параметров]
    I --> E[Обогащение данных]
    E --> V[Проверка данных]
    V --> S[Скоринг]
    S --> D{Решение}
    D -->|Одобрено| O[Предложение условий]
    D -->|Другие условия| O
    D -->|Нужны документы| DOC[Загрузка документов]
    DOC --> V
    D -->|Отказ| R[Отказ + причина]
    O --> SIGN[Мок-подписание]
    SIGN --> ISSUE[Мок-выдача]

    V -. спорная/аномальная заявка .-> B[Банкир]
    S -. спорная заявка .-> B
    B --> BD{Решение банкира}
    BD -->|Одобрить| O
    BD -->|Изменить условия| O
    BD -->|Запросить данные| DOC
    BD -->|Отказать| R
```

## Роли
- Клиент: создаёт/редактирует/отправляет заявку, загружает документы, принимает условия.
- Система: валидирует, обогащает, вызывает моки, считает скоринг, формирует решение.
- Моки: ЕГРЮЛ/ЕГРИП, прозрачность бизнеса, БКИ.
- Банкир: обрабатывает спорные заявки и принимает ручное решение.

## Ключевой принцип
Автоматический happy path не должен требовать участия банкира. Банкир подключается только при спорных правилах, недостатке данных или ручном override.
