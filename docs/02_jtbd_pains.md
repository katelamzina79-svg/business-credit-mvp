# День 1 — JTBD и боли

## JTBD клиента
**Основная работа:**
Когда бизнесу нужны деньги для оборота, закупки или развития, я хочу быстро понять, какой продукт и сумма мне доступны, подать заявку без повторного ввода уже известных банку данных и получить понятное решение, чтобы продолжить работу бизнеса без лишней бюрократии.

### Functional jobs
1. Выбрать подходящий продукт.
2. Указать ИНН и потребность в финансировании.
3. Проверить автоматически найденные данные компании.
4. Указать сумму, срок и назначение.
5. Узнать статус заявки.
6. Понять причины решения.
7. Дозагрузить документы, если они нужны.
8. Принять предложенные условия и пройти мок-подписание.

### Emotional jobs
- Не чувствовать, что заявка «ушла в чёрный ящик».
- Понимать, что происходит с заявкой.
- Не бояться, что отказ означает ошибку без объяснения.

## JTBD банкира
Когда приходит заявка малого бизнеса, я хочу видеть структурированные данные компании, результаты внешних проверок и скоринга в одном месте, чтобы быстро принять решение по стандартным заявкам и вручную разобрать только спорные случаи.

## Боли клиента
| Боль | Последствие | Решение MVP |
|---|---|---|
| Повторный ввод данных | Дольше заполнение, ошибки | Автозаполнение по ИНН |
| Непонятный статус | Тревога, обращения в банк | Timeline |
| Непонятный отказ | Недоверие | Reason code человеческим языком |
| Неясно, какие документы нужны | Повторные отправки | Чёткий список документов |
| Сложно выбрать продукт | Ошибочный выбор | Каталог + краткое сравнение |

## Боли банка
| Боль | Последствие | Решение MVP |
|---|---|---|
| Неполные данные | Ручные уточнения | Валидация до скоринга |
| Много ручной работы | Низкая скорость обработки | Автоматические проверки |
| Разрозненные результаты | Ошибки решения | Единая карточка заявки |
| Спорные кейсы | Риск автоматической ошибки | Очередь банкира |
| Нет аудита | Нельзя восстановить путь решения | История статусов + аудит |
